About NZ Freeview

A television streaming PWA combining adaptive video, a custom programme-guide API and session-aware channel access.

Application architecture

Built with HTML, CSS and vanilla JavaScript, with separate scripts for guide data, rendering, playback, authentication and panels. A central configuration maps channel names, guide IDs, numbering, logos and stream overrides. Guide rows are reused by channel ID, updating text in place rather than rebuilding the entire list each minute.

XMLTV guide pipeline

A custom C# / ASP.NET Core API loads XMLTV schedules into a channel index and serves a compact JSON summary of current and upcoming programmes. The app polls that summary every minute and caches playlist metadata for 30 minutes. Schedule times are normalised to Unix timestamps; channel aliases link different source names. The +1 channels use their own delayed streams and API listings.

Streaming lifecycle

HTML5 video is managed through Video.js for HLS and dash.js for MPEG-DASH, with player libraries loaded on demand. Channel changes dispose the previous player and invalidate its callbacks so late events cannot interrupt a newer stream. The DASH path also supports configuring a Widevine licence server through an ASP.NET proxy.

Recovery and playback monitoring

Guide requests are shared while in flight, with exponential retry delays and the last successful listings retained in memory. Playback monitoring checks the media clock as well as buffering events. Advancing video cancels the stall timer; prolonged buffering shows a notice while allowing the player to recover. Startup failures and fatal playback errors follow a separate cleanup path.

Authentication and preview policy

C# ASP.NET handlers on IIS validate POSTed credentials against the shared user file and issue an encrypted, Secure, HttpOnly, SameSite login cookie valid for 30 days. It restores the server session after reopening the app; signing out clears it, and account-file changes invalidate it. The app checks session status to control sports visibility. TVNZ guest previews share a two-minute window and a 30-minute cooldown, persisted in localStorage across reloads and communicated between tabs. Signing in cancels the preview timer; signing out stops restricted playback. These browser controls demonstrate the access policy; they do not protect the upstream stream URLs.

Mobile layout and PWA caching

Dynamic viewport units, edge-to-edge layout and safe-area insets keep video full size while positioning controls around screen cutouts. Playback switches the theme colour to black. A web app manifest supports installation, while a service worker revalidates static assets and falls back to saved copies when the network fails. Video, guide API and session requests bypass that static cache. The About sheet uses a native dialog; the account drawer manages keyboard focus.

Verification

Regression checks use the Node.js test runner and isolated JavaScript contexts to exercise guide mapping, retries, buffering, sessions and preview deadlines. Browser checks combine real HLS playback with simulated authentication responses to verify channel visibility, login/logout transitions and portrait/landscape layouts.
